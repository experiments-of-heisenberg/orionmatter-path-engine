## Bug hunt: one real bug

**Tornado pay-band bar marks no option current for B1/B2 floors** — [sensitivity.ts](/agent/workspace/orionmatter-path-engine/src/lib/whatif/sensitivity.ts) lines 130–141. The bar only tries `no floor, B3, B4, B5` (`BANDS.slice(2)`), so when `constraints.minCompBand` is `"B1"` or `"B2"` (both valid per the `Constraints` schema), every option has `current: false`, breaking the "exactly one current per bar" invariant the existing tests pin for other floors. Concrete input: sample engineer with `{ minCompBand: "B2" }` — verified `current options: []`. Suggested fix: mirror `monthsBar` and union the person's own band into the tried values (ordered no-floor-first, then ascending), so the baseline is always represented. No failing test was written for it, per the rules.

Checked and found correct: both relaxation loops (bounds, direction, termination, steps counting), bar tie-break (`-swing`, then build order) and worst/best first-listed ties, B1 search (only "no floor" tried), unknown band labels via unvalidated input (loop is empty, no crash).

## Doubts

- `to: "no floor"` for pay appears unreachable in this cohort: B1/B2 filter nothing (no B1 endings exist), so the search always stops at B2/B1 first, or the floor was already met. The code path is correct, just dead on this data.
