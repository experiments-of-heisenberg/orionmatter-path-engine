## Bugs and doubts (nothing fixed, per instructions)

No definite bugs found. Four observations, all confirmed by reading plus a runtime probe:

1. **Redundant notes on duplicate skill add** ([apply.ts](/agent/workspace/orionmatter-path-engine/src/lib/whatif/apply.ts):208-212). Adding an already-present skill yields two notes (`"rust" was already in your skills list.` plus `Skills to add was already rust.`) because the de-dup guard checks for the field label, which the skill-specific note doesn't contain. Cosmetic. Suggested fix: skip the generic "already" note when this change already added a note (compare `notes.length` before/after the switch).
2. **Empty skills array passes the schema** ([schemas.ts](/agent/workspace/orionmatter-path-engine/src/lib/whatif/schemas.ts):52, `value` has no `.min(1)`). It produces a spurious `Skills to add was already none.` note. Suggested fix: `.min(1)` on the array, or skip empty changes in `applyChanges`.
3. **Quote guard is substring-based, so short phrases false-positive** ([apply.ts](/agent/workspace/orionmatter-path-engine/src/lib/whatif/apply.ts):38-41). Verified: `phraseInText("go", "I want to reach my goal")` is `true`. Probably accepted design (matches the critic's guard), but a quoted skill like "go" can pass on an unrelated word. Word-boundary matching would tighten it at some recall cost.
4. **Time-limit check is silent when no route has a timeline** ([conflicts.ts](/agent/workspace/orionmatter-path-engine/src/lib/whatif/conflicts.ts):55-58). If `maxMonths` is set but every route's `monthsToGoal` is null, `fastest` is undefined and no conflict is reported — even though nobody ever reached the goal. The `twins.n === 0` case is covered; the "twins exist, none reached" case is not. Flagging as a question for the maintainer rather than a bug.
