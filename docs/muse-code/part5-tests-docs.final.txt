Bugs / doubts found in `src/` (not fixed, no failing tests written; all verified by running the actual functions):

1. `numbersIn` counts digits glued to letters on the right ([textChecks.ts](/agent/workspace/orionmatter-path-engine/src/lib/skeptic/textChecks.ts:31)). `"the 1st step"` gives `[1]`, `"6pm"` gives `[6]`, though the docstring says digits glued to letters are not numbers. The lookbehind guards only the left side, so ordinals in ordinary prose ("1st", "2nd", "3rd") need to be in the evidence or they trigger `ungrounded_number`. Suggested fix: add a negative lookahead such as `(?![A-Za-z])` after the number group.
2. `numbersIn` splits thousands separators: `"1,000 engineers"` gives `[1, 0]` (same line). Suggested fix: allow commas inside digit groups.
3. `findOverclaim` matches inside hyphenated compounds ([textChecks.ts](/agent/workspace/orionmatter-path-engine/src/lib/skeptic/textChecks.ts:16)) because `\b` treats `-` as a boundary: `"will-power"` returns `"will"`, so "never-ending" / "always-on" would also flag. Suggested fix if this is unwanted: custom boundaries like `(?<![A-Za-z-])…(?![A-Za-z-])` instead of `\b`.
4. Minor: `numbersIn(".5 chance")` gives `[]` — leading-dot decimals are never recognised (same line as 1). Probably fine for prose, noting for completeness.
