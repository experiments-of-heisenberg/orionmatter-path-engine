## Project

- Name: orionmatter-path-engine
- What it is: a multi-agent career route planner for engineers, built for the Meta Global AI Developer Hackathon.
- Stack: TypeScript (strict), Zod, Vitest, ESLint, Prettier. Next.js UI arrives in Part 11.

## Common Commands

- Test: `npm test`
- Everything CI runs: `npm run check` (typecheck, lint, format check, tests, secret scan)
- Format: `npm run format`

## Project Layout

- `src/lib/`: domain logic. `schemas.ts` holds Zod schemas; `tools/` holds deterministic tools; `env.ts` validates configuration.
- `src/lib/tools/`: pure functions over the synthetic cohort, called through `EvidenceLedger`.
- `tests/`: Vitest tests. `scripts/`: dev and diagnostic scripts. `data/`: JSON data.
- `docs/`: `api-notes.md`, `adr/` (architecture decisions), `parts/` (one page per build part), `muse-code/` (evidence of Muse Code work; do not edit).

## Architecture rules (do not break these)

1. **LLMs plan and narrate; tools compute.** Every number shown to a user comes from a deterministic tool result, never from model output.
2. **Every claim cites evidence.** A claim carries `evidenceIds` from the `EvidenceLedger`; code rejects claims whose ids or numbers do not match.
3. **Ranges, never single numbers.** Outcomes are percentile ranges with a sample size `n`. If `n < 15`, mark the segment `evidenceThin`.
4. **Validate every boundary with Zod.** Model output, tool arguments, API request bodies and environment variables are untrusted until parsed.
5. **No employer-side features.** This is a planning tool for individuals. Never add candidate screening, ranking or filtering.

## Code conventions

- TypeScript strict mode with `noUncheckedIndexedAccess`. No `any`; use `unknown` and narrow it. Do not silence lint with disable comments unless you explain why.
- Every file starts with a header comment saying what it does and why it exists. Every exported function has JSDoc covering inputs, outputs and the reason it exists. Comment non-obvious logic; do not narrate obvious code.
- Small files, one responsibility each. Prefer pure functions. Inject dependencies (such as the model client) so code is testable offline.
- Errors: throw typed errors for programmer mistakes; return result objects for expected failures such as bad model output.
- Never write `process.env` access outside `src/lib/env.ts`.

## Testing

- Unit tests must be deterministic and offline. Never call live model APIs from tests; use fixtures or the mock model client.
- Add tests with every change. A change is done only when `npm run check` passes.

## Safety

- Never print, log, commit or read back API keys. Do not create files containing secrets. `.env.local` is git-ignored.
- Do not make network requests other than to the documented model APIs.
- Do not commit, amend or push unless asked. Do not edit `docs/muse-code/` or generated `data/cohort.synthetic.json` by hand (regenerate with `npm run gen:cohort`).
